# eduroam-goe-linux

A modified Go port of the eduroam CAT Linux installer for the University of Göttingen
(`eduroam-linux-University_Goettingen-University_of_Gottingen.py`), with a
terminal UI built on [Bubble Tea](https://github.com/charmbracelet/bubbletea)
and pluggable network management backends.

## Reference implementation

The main file this project is based on and checked against is the Python
installer in this repository:

**[`eduroam-linux-University_Goettingen-University_of_Gottingen.py`](eduroam-linux-University_Goettingen-University_of_Gottingen.py)**

It was generated by the GÉANT eduroam CAT for the University of Göttingen
profile, from CAT's `devices/linux/Files/main.py`. It was written by
**Tomasz Wolniewicz** and **Michał Gasewicz** (NetworkManager support), with
contributions from Steffen Klemer, ikreb7, Dimitri Papadopoulos Orfanos,
sdasda7777, Matt Jolly, Benoit LE TEXIER and jmontes (see [Credits](#credits)).
This project would not exist without their work.

The behaviour of the Go code follows that script. This includes the
installation flow, username validation, CA handling, NetworkManager
connection settings, and the wpa_supplicant and iwd output. Where this port
deliberately differs, the difference is described below or in
[NOTICE](NOTICE).

## Design decisions

### No desktop-environment detection, no GUI dialog fallbacks

The original script probes the session (`KDE_FULL_SESSION`,
`GNOME_DESKTOP_SESSION_ID`, `xprop` for XFCE, `$DISPLAY`). It then picks a
dialog frontend from `yad`, `zenity`, `kdialog` and `tkinter`, falling back
to plain `input()` prompts. This port removes all of that logic and uses one
terminal UI (Bubble Tea) everywhere, for two reasons:

1. **tkinter is not always available.** Many distributions package tkinter
   separately from the Python interpreter (for example `python3-tk` or
   `python-tkinter`). Minimal and server installations often lack it, so the
   tkinter fallback cannot be relied on.
2. **Checking for a list of desktop environments and dialog tools bloats the
   system.** Supporting a GUI on every desktop means depending on, or probing
   for, several external programs (`xprop`, `yad`, `zenity`, `kdialog`). Each
   program brings its own toolkit and behaves slightly differently. A single
   self-contained TUI behaves the same on every desktop, on a bare TTY and
   over SSH, with no extra packages.

The "ask the user" step is still there, now as screens in the TUI. The
"which network stack" question moved into a **backend interface**
(`internal/backend`): NetworkManager, iwd and wpa_supplicant are
implementations of it, and the TUI lets the user pick from the backends
detected on the system.

### No dbus-python (or any other Python module)

The original script needs `dbus-python` to talk to NetworkManager, and
`cryptography` or `pyOpenSSL` to read a PKCS#12 user certificate. Like
tkinter, these are separate distribution packages (`python3-dbus`, which
also links against the C `libdbus`, and `python3-cryptography`), so the
installer can fail on systems that do not have them. This port drops both:

- **D-Bus:** [`godbus/dbus`](https://github.com/godbus/dbus) speaks the D-Bus
  wire protocol in pure Go. No `dbus-python` and no `libdbus` are needed,
  only a running system bus and NetworkManager.
- **PKCS#12:** [`go-pkcs12`](https://software.sslmate.com/src/go-pkcs12)
  decodes certificates in pure Go. The `openssl` command is only used as an
  optional fallback, for legacy-encrypted files and for hashing a CA
  directory.

The result is one statically linked binary (`CGO_ENABLED=0`) with no
runtime dependencies besides the network stack it configures.

## Build & run

```sh
go build -o eduroam-installer ./cmd/eduroam-installer
./eduroam-installer                 # interactive TUI
./eduroam-installer --list-backends # show detected backends
./eduroam-installer -s -u max@uni-goettingen.de -p 'secret'   # headless
```

Flags: `--debug/-d`, `--username/-u`, `--password/-p`, `--silent/-s`,
`--pfxfile`, `--backend <id>`, `--wpa_conf`, `--iwd_conf`, `--wired`
(silent mode), `--list-backends`, `--about`, `--version`.

Prebuilt Linux binaries (amd64, arm64, 386, armv7) are attached to each
[GitHub release](https://github.com/SepehrRajabi/eduroam-goe-linux/releases),
together with a `SHA256SUMS` file:

```sh
sha256sum -c --ignore-missing SHA256SUMS
tar xzf eduroam-installer_<tag>_linux_amd64.tar.gz
```

## CI and releases

- **`.github/workflows/ci.yml`** runs on pushes to `main` and on pull
  requests. It checks `gofmt` and `go mod tidy`, runs `go vet` and
  `go test -race`, cross-builds the binary for every release architecture
  with a smoke run (`--version`, `--about`, `--list-backends`), and runs
  `govulncheck`.
- **`.github/workflows/release.yml`** runs when a `v*` tag is pushed. It
  repeats the tests and the vulnerability check, builds the binaries from
  that tag (version set with `-X main.version=<tag>`), packages each one with
  LICENSE, NOTICE and README, writes `SHA256SUMS`, generates the changelog
  and publishes a GitHub release. Tags containing `-` (for example
  `v1.0.0-rc1`) are marked as pre-releases.
- **`scripts/changelog.sh [tag]`** prints the commits between the previous
  tag and the given one as Markdown. The release uses it, and you can run it
  locally to preview the notes.

To cut a release:

```sh
git tag -a v0.1.0 -m "v0.1.0"
git push origin v0.1.0
```

## Layout

| Path | Purpose |
|---|---|
| `cmd/eduroam-installer` | CLI flags, silent mode, starts the TUI |
| `internal/profile` | Institution config (`Config`) and messages; CA embedded from `ca.pem` |
| `internal/creds` | Username/password validation, PKCS#12 identity extraction |
| `internal/store` | `$XDG_CONFIG_HOME/cat_installer` (CA, `user.p12`, generated files) |
| `internal/backend` | `Backend` interface + registry |
| `internal/backend/networkmanager` | NetworkManager via system D-Bus |
| `internal/backend/iwd` | iwd provisioning files (`/var/lib/iwd/<ssid>.8021x`) |
| `internal/backend/wpasupplicant` | wpa_supplicant config file |
| `internal/sysinfo` | Wired interface detection |
| `internal/tui` | Bubble Tea frontend |
| `scripts/changelog.sh` | Release-notes generator |
| `.github/workflows` | CI and tag-triggered releases |

## Adding a backend

Implement `backend.Backend` (`Info`, `Probe`, `Supports`, `Install`) in a new
package, call `backend.Register` from its `init`, and blank-import the
package in `cmd/eduroam-installer/main.go`. The TUI lists it automatically.

## TUI

Full-screen layout: a header with the step counter, a sidebar with progress
and a summary of the choices made so far (hidden on terminals narrower than
84 columns), the main panel, and a footer with the keys for the current
screen. `ctrl+r` reveals password fields and `esc` asks before quitting.
